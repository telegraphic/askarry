Inside Askarry

Askarry is the retrieval system on which the atlas runs: it indexes the AASKAII book, the 2015 book and the SKA key-capability documents, and exposes them to Claude through a Model Context Protocol server. This page describes the retrieval pipeline as the code configures it and lists every tool the server offers, read directly from the source.

Retrieval pipeline

Ingestion parses each PDF with Docling and splits it with a hybrid chunker into passages of at most 480 tokens, a limit chosen to stay below the 512-token window of the embedding model with room for its special tokens. Each passage is embedded with BAAI/bge-large-en-v1.5 and stored in ChromaDB, and the same passages feed a BM25 keyword index; acronyms that the chapters define inline are harvested at the same time, so a query for "RFI" also searches for "radio frequency interference".

A query therefore runs down two legs at once. The semantic leg retrieves passages whose embeddings lie near the query, the keyword leg retrieves those that share its terms, and Reciprocal Rank Fusion with k = 60 merges the two rankings, the keyword leg weighted at half the semantic one. A cross-encoder, cross-encoder/ms-marco-MiniLM-L-6-v2, then rescores the fused pool against the query, and passages from the 2015 book have their scores multiplied by 0.85, so that an older source outranks a newer one only when it is genuinely the better match. Finally each surviving passage is widened with its neighbouring chunks, two on each side when the request comes through the MCP server, so the model reads whole arguments rather than fragments.

Two consumers sit on top of this pipeline. The Gradio application answers questions with a local model through Ollama, passing it the top five passages; the MCP server hands Claude the top twenty, because a frontier model can synthesise many more passages than a small local one. The atlas uses only the second route.
