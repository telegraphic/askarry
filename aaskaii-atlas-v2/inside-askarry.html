Inside Askarry

Askarry is the retrieval system on which the atlas runs. It indexes the AASKAII book, the 2015 book and the SKA key-capability documents, and it makes them available to Claude through a Model Context Protocol (MCP) server. This page describes the retrieval pipeline as the code configures it. It also lists every tool that the server offers, read directly from the source code.

Retrieval pipeline

During ingestion, Docling parses each PDF and a hybrid chunker splits it into passages of at most 480 tokens. This limit keeps each passage below the 512-token window of the embedding model and leaves room for its special tokens. The model BAAI/bge-large-en-v1.5 embeds each passage, and ChromaDB stores the result. The same passages also feed a BM25 keyword index. At the same time, ingestion collects the acronyms that the chapters define, so a query for "RFI" also searches for "radio frequency interference".

A query therefore follows two paths at once. The semantic path retrieves passages whose embeddings lie close to the query, and the keyword path retrieves passages that share its terms. Reciprocal Rank Fusion with k = 60 then merges the two rankings, giving the keyword path half the weight of the semantic one. Next, a cross-encoder, cross-encoder/ms-marco-MiniLM-L-6-v2, rescores the merged passages against the query. Passages from the 2015 book have their scores multiplied by 0.85, so that an older source outranks a newer one only when it is genuinely the better match. Finally, each remaining passage is widened with its neighbouring passages, two on each side when the request comes through the MCP server. The model therefore reads whole arguments rather than fragments.

Two applications use this pipeline. The Gradio application answers questions with a local model through Ollama and passes it the top five passages. The MCP server passes Claude the top twenty, because a large model can combine many more passages than a small local one. The atlas uses only the MCP server.
