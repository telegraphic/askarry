Behind the Atlas

Version 1 of the atlas was assembled in August 2026 by sixteen agent runs working with the six tools the retrieval server then offered, so most of its figures were tallied by hand or reconstructed from search results. Version 2 separates what can be computed from what must be read: a script computes every count directly from the indexed book, agents read the chapters only to extract requirements and open questions, and a second script checks every sentence the agents quote before any page uses it.

How version 2 was built

The first stage is deterministic. scripts/build_atlas_data.py calls the corpus tools that now exist for the purpose, among them exact keyword coverage, the facility network, the citation and source databases and the scheduling model, and writes one JSON file per page with the commit and date it was built from. Every figure on the reference and analysis pages comes from those files, so rerunning the script regenerates the atlas's numbers rather than asking an agent to recount them. Counts are restricted to the book's chapters: the index also holds re-downloaded copies of a few chapters and two documents that are not chapters, and counting them would have credited some chapters twice.

The second stage reads. Seven agents, one for each book section, searched every chapter of their section for stated instrument requirements and for statements of open questions, copying the sentence behind each and writing a summary of the section's demands. Two further agents then worked through the results: one reran every requirement that states enough parameters through the live sensitivity calculator, and the other asked, for every requirement, whether the defined observing contexts or only the full AA4 design can deliver it. The third stage is again mechanical. scripts/verify_atlas_quotes.py looks for each quoted sentence in the chapter it names and admits a row only if the sentence is there, which is how version 2 guards against the citation swap that version 1 published.

Known limitations

Several limits remain, and they are stated here rather than left for a reader to discover. Keyword counts measure how often a chapter names a mode, technique or risk, not how much weight it gives it; a chapter counts once it names a term twice. The requirement register samples what chapters state in numbers and is not a specification of the telescopes. Eleven chapters have no PDF on skao.int, ten because they are not yet on the book's page and one because its listed link is broken, so they contribute no counts; the directory lists them with a link to the book's page. The index also contains a stray file, filed as Bianchi01 among the working-group overviews, which is in fact a copy of the Cradle of Life overview (Bianchi02); the atlas counts it once under the right identifier, but the index itself should be corrected.

The time-demand analysis rests on one reviewed extraction of observing requests and on scheduling settings that are unverified defaults, so it measures relative pressure between science cases rather than an allocation. The section summaries, finally, are the reading agents' synthesis: they were written from what the agents retrieved and in the voice the atlas asks for, but unlike the quotations they were not checked sentence by sentence.

Rebuilding the atlas

python scripts/build_atlas_data.py        # every count, from the index and databases
python scripts/verify_atlas_quotes.py     # check agent quotes, write data/prose.json
python -m http.server 8765 --directory aaskaii-atlas-v2

The agent stage is the Claude Code workflow scripts/atlas_prose_workflow.js, run with args.argsPath pointing to data/agents/workflow_args.json, which the build script writes: the per-section chapter lists and coverage counts. Its raw output is kept in data/agents/sections.json, so the verification step can be rerun without repeating the reading.
