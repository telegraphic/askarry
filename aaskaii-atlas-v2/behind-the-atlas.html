Behind the Atlas

Version 1 of the atlas was assembled in August 2026 by sixteen agent runs. They worked with the six tools that the retrieval server then offered, so most of their figures were tallied by hand or rebuilt from search results. Version 2 separates what can be computed from what must be read. A script computes every count directly from the indexed book. Agents read the chapters only to extract requirements and open questions. A second script then checks every sentence that the agents quote before any page uses it.

How version 2 was built

The first stage is deterministic. The script scripts/build_atlas_data.py calls the corpus tools built for the purpose. These include exact keyword coverage, the facility network, the citation and source databases and the scheduling model. The script writes one JSON file per page and records the commit and date it was built from. Every figure on the reference and analysis pages comes from those files. Running the script again therefore regenerates the atlas's numbers, without asking an agent to recount them. The counts include only the book's chapters. The index also holds re-downloaded copies of a few chapters and two documents that are not chapters, and counting them would have credited some chapters twice.

The second stage reads the chapters. Seven agents, one for each book section, searched every chapter of their section for stated instrument requirements and open questions. They copied the sentence behind each one and wrote a summary of the section's demands. Two further agents then worked through the results. One reran every requirement that states enough parameters through the live sensitivity calculator. The other asked, for every requirement, whether the defined observing contexts can deliver it or whether it needs the full AA4 design. The third stage is mechanical again. The script scripts/verify_atlas_quotes.py looks for each quoted sentence in the chapter it names and admits a row only if the sentence is there. This check guards against the kind of citation swap that version 1 published.

Known limitations

Several limits remain, and they are stated here so that you need not discover them yourself. Keyword counts measure how often a chapter names a mode, technique or risk, not how much weight it gives it, and a chapter counts once it names a term twice. The requirement register samples what chapters state in numbers. It is not a specification of the telescopes. Eleven chapters have no PDF on skao.int, so they contribute no counts. Ten are not yet on the book's page, and the listed link for the eleventh is broken. The directory lists them with a link to the book's page. Finally, the index contains a stray file, filed as Bianchi01 among the working-group overviews. It is in fact a copy of the Cradle of Life overview, Bianchi02. The atlas counts it once under the right identifier, but the index itself should be corrected.

The time-demand analysis rests on one reviewed extraction of observing requests and on scheduling settings that are unverified defaults. It therefore measures the relative pressure between science cases, not an allocation. The section summaries are the reading agents' own synthesis. The agents wrote them from what they retrieved and in the voice the atlas asks for. Unlike the quotations, however, the summaries were not checked sentence by sentence.

Rebuilding the atlas

python scripts/build_atlas_data.py        # every count, from the index and databases
python scripts/verify_atlas_quotes.py     # check agent quotes, write data/prose.json
python -m http.server 8765 --directory aaskaii-atlas-v2

The agent stage is the Claude Code workflow scripts/atlas_prose_workflow.js. It runs with args.argsPath pointing to data/agents/workflow_args.json, a file that the build script writes with each section's chapter list and coverage counts. The workflow's raw output is kept in data/agents/sections.json, so the verification step can be rerun without repeating the reading.
