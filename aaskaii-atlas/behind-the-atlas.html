What this page is

Parts I–III of this atlas present findings. This part shows the work behind them. A document-retrieval MCP server was queried through a fleet of parallel research agents. The process paused twice for a human decision. A small set of ground rules was fixed before research began. Those rules make the three documents comparable to each other, rather than three independently styled write-ups.

Known issues

Note this is an exploratory prototype, and some clear issues are apparent. Some known issues:

  • Not all PDFs are available on the AASKA II website, so some science cases are missing.
  • It invented a set of 7 science themes instead of using the book chapter sections, so the 2015 vs. 2026 science case comparison mixes the made-up themes with actual sections.
  • Some acronyms are mis-categorized (e.g. FPGA is listed as an Organization).
  • The 'contention' is really just a list of most used observing modes and not indicative of scheduling contention.
  • The nuances of construction are not reflected in the Capability Crosscheck, leading to some unreasoanble conclusions.
  • On Sensitivity verification page, it looks like it picked up a citation swap (i.e. a hallucination).

The knowledge base

All three documents draw on one MCP (Model Context Protocol) server, astronomy-rag. It connects through the desktop bridge. It runs a hybrid retrieval pipeline over the AASKAII PDF corpus. Semantic vector search and BM25 keyword search run in parallel. Reciprocal Rank Fusion combines their results. A cross-encoder then re-ranks the combined list. Every search returns passages with a source title, section, and page number attached. That attached metadata is what makes line-by-line sourcing possible.

Orchestration pipeline

One MCP server is read by many short-lived research agents, not one long session. Each agent receives a narrow brief. Each agent runs its own searches. Each agent then hands back sourced findings for the orchestrating session to compile.

Step 1

Load the deferred MCP tools

The astronomy-rag tools are not in the base tool list. Each agent's first move is a ToolSearch call that names the exact tools it needs. Each agent then calls list_documents to see the section-by-paper map before it searches anything.

Step 2

Fan out one agent per thematic section

Seven agents launched in one batch. Each agent received a self-contained brief. Each brief listed the full paper set for its section and the fixed observing-mode taxonomy to tag against. Each brief also instructed the agent to run several targeted searches per sub-theme, not one broad query.

Step 3

Track progress with a shared task list

TaskCreate and TaskUpdate kept one task per section visible throughout. Each task was marked in-progress on spawn and completed on return. This produced the same list a viewer would have seen updating live.

Step 4

Resume, don't restart, for follow-up questions

Part II's open-questions and instrument-requirements asks went back to the same seven agents by name via SendMessage. Those agents already had the papers loaded. The follow-up therefore only needed new searches for what was not asked the first time. One attempted resume batch hit a transient API session limit. Retrying the same messages a few minutes later succeeded.

Step 5

Run corpus-wide sweeps where section boundaries don't apply

The cross-cutting methods ranking needed the opposite approach from the section fan-out. Two fresh agents ran a fixed 16-keyword list as independent whole-corpus searches. Each agent then reported which of the 7 sections each technique surfaced in.

Step 6

Deliver as files, not published pages

The first attempt to publish Part I as a hosted claude.ai Artifact was declined. Every document since, including this one, is instead delivered as a self-contained HTML file via direct file transfer. Each file is styled identically to what a published Artifact would have looked like.

Questions actually asked

The process stopped and asked at two points in this project, rather than assuming an answer. Both stops happened because the choice materially changed the scope of work. Neither stop happened because the request was unclear.

Asked before Part I began

Which generation of the science book should the analysis cover?

The corpus holds two overlapping books. The current 2026 AASKAII has 7 sections and about 189 papers. The older 2015 AASKA I adds 9 more sections and about 157 papers. Including both books would double the research effort.

chosen → AASKAII only — current 2026 book, 7 sections, fastest, reflects the latest science case
AASKAII + legacy AASKA — all 16 sections, ~306 papers, roughly double the effort
Let me pick sections — a custom subset
Asked before Part III began

How to get the network graph from a different, unreachable conversation?

Sessions do not share memory or files with each other. No published artifact or running session matched "the analysis project ideas chat." This was a genuine blocker, not a judgment call.

Sourcing discipline

The same three rules were repeated verbatim in every agent's brief across both parts. A language model can quietly relax these rules under pressure to fill in a table cell, so the brief restated them each time.

Rule 1

Report only what a search actually returned

Every agent was told explicitly not to guess a paper into a category it did not surface for. The Part II keyword-sweep agents both noted, unprompted, papers they suspected were relevant. They excluded those papers anyway because the search did not confirm the connection.

Rule 2

A blank cell means the paper didn't say, not that Claude didn't look

Field of view and survey speed are blank for most pointed and triggered observations across the requirements ledger. Those values are genuinely absent from the source papers. They are not an unfilled gap in the search.

Rule 3

Flag reconstructions as reconstructions

Part III states outright, in its own footer, that it rebuilds a finding from a written summary rather than the original dataset. This is the honest version of "citation needed" for a source this process could not reach.
