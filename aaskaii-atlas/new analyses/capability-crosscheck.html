SKAO · AASKAII — Cross-Corpus Analysis, Part IX

Capability Cross-Check

The instrument-requirements ledger (Part II·C) records what science papers say they need. It was never checked against what SKAO's own engineering documents say the telescopes can actually deliver. This page runs that check for the first time, using the separate, smaller "SKA key capabilities" document set (search_ska_capabilities) — six months into this atlas's existence, its two calculator-adjacent tools had never once been called.

Scope & method

Twelve requirements were selected from the ledger for cross-checking, each picked to test a distinct kind of capability question: array-assembly stage (AA* vs. AA4), Band 5a/5b's 80-dish restriction, VLBI baseline reach, beamformer/correlator limits, and transient-buffer throughput. Each was checked against search_ska_capabilities, a document set that has never been touched by any earlier pass in this atlas, and given one of four verdicts: confirmed, partially confirmed, not addressed, or contradicted — assigned only on the basis of what the capability docs actually state, never assumed either way when they're silent.

The capability document set

Seven documents, entirely engineering-facing — well suited to checking feasibility, not to validating science justification.

The funding finding

Four requirements assume a stage that isn't just "not yet built" — it's "not yet funded," and neither is the stage below it

A-06, C-09, D-05, and E-05 all explicitly require AA4/design-baseline capability. Sridhar et al. (2025) confirms plainly that funding for the full design baseline "has not yet been fully secured" — but the same document goes further: "Due to inflationary pressures caused by recent geopolitical events, the funding originally secured to construct AA* is no longer sufficient... [SKAO is] seeking additional funding." That is: even AA*, the intermediate array this entire atlas and the YITL operations report treat as the near-term baseline, is confirmed as currently underfunded. Every AA4-scoped requirement in the ledger sits on ground that's doubly unconfirmed — the target stage and the stepping-stone beneath it.

Broader patterns

The 80-dish blind spot

C-01 and E-08 share a distinct pattern: capability docs only ever quantify Band 5a/5b sensitivity for the full 133-dish design-baseline sub-array, never separately for the 80-dish subset actually equipped under AA*. Every Band-5-specific science case in the ledger implicitly assumes the smaller subarray behaves like the fully-populated one — an assumption the capability docs neither confirm nor deny, since they simply don't publish that number.

Architecture-fixed, not funding-fixed, limits

E-09, F-05, and B-10 hit fixed correlator/beamformer ceilings — 16 PST beams, VLBI's FoV-vs-sensitivity trade-off, VLBI astrometric precision — that are independent of array-assembly stage. These will persist even once AA4 is fully funded and built, unlike the AA*→AA4 gaps above which are purely capacity/funding issues.

Where the docs simply go quiet

C-09 and D-08 got no matching passage at all, despite both papers stating fairly specific figures. This doesn't mean the figures are wrong — it means this particular engineering corpus doesn't happen to address them, a genuine and useful "not addressed" rather than a disagreement.

Sourcing discipline: confirmed/partial/not-addressed/contradicted verdicts reflect only what search_ska_capabilities actually returned; silence in the capability docs was reported as "not addressed," never treated as either confirmation or denial.

What this page is not: a judgement on whether the science cases themselves are sound — only on whether the specific capability assumption each one leans on is currently documented as deliverable.
